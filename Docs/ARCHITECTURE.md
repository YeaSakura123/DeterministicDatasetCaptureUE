# Architecture and determinism contract

## Goal

The plugin treats dataset generation as an offline simulation rather than a screenshot utility. A sample is valid only when every modality and its metadata refer to the same evaluated logical frame. Repeated jobs must prove exact metadata and auxiliary-buffer replay; renderer-dependent color may use a declared numeric tolerance with a generated heatmap.

## Frame pipeline

```text
fixed engine tick
  -> pre-actor: evaluate Sequencer at absolute time
  -> pre-actor: discover/seed/seek Niagara components
  -> pre-actor: call custom deterministic drivers
  -> normal actor, animation, physics and component ticks
  -> post-actor: record native Chaos transforms or random-access/apply the cached logical frame
  -> post-actor/end-of-frame: record or verify native Niagara CPU/GPU Sim Cache payloads
  -> post-actor: resolve the active camera
  -> capture HR
  -> capture isolated native-HR linear HDR
  -> render spatially supersampled reference HR and downsample to a fixed grid
  -> derive LR from HR, or render native LR without ticking
  -> capture float SceneDepth without ticking
  -> render independent Slate/UMG game-layer RGBA and reject visible WidgetComponents
  -> optionally arm AfterDOF and after-tonemap real Main View RDG extraction
  -> render the player Main View at LR internal / HR display size
  -> next pre-actor callback: read back and commit the pending sample
  -> atomically write files and manifest hashes
```

Warmup ticks also submit each enabled SceneCapture without writing files. This initializes the persistent per-modality View State before frame zero; without render warmup, the first native LR frame showed repeat-run differences even when simulation state and all auxiliary buffers matched.

`FrameStep` normally skips writes while still evaluating intermediate simulation frames, so particles, animation events and physics do not jump over time. FG replay roles may also suppress the player Main View on uncaptured ticks. This prevents an intermediate render from advancing endpoint View State while the world simulation still advances at every fixed tick.

## Control matrix

| Content | Control mechanism | Guarantee within one job | Replay requirement |
|---|---|---:|---|
| Sequencer transforms/camera/animation/events | continuous `SetPlaybackPosition(..., Play)` at absolute time | exact frame evaluation | author the content in the Level Sequence |
| Skeletal animation outside Sequencer | fixed engine delta plus portable component-space pose cache | exact cached pose replay at captured endpoints | external gameplay/AnimBP inputs must be deterministic while recording the cache |
| Legacy Cascade particles | fixed engine delta and seeded global random stream | stable sequential playback | use seeded particle modules for strict repeatability |
| Niagara CPU/GPU | Desired Age, fixed seek delta, forced solo, deterministic system seed/fixed tick plus optional native all-attribute Sim Cache and immediate GPU readback | exact requested age and fixed-topology cached CPU/GPU particle payload | custom-storage or externally driven Data Interfaces still need a deterministic project adapter and strict preflight classification |
| Chaos static-mesh rigid bodies | fixed engine delta, `p.Chaos.Solver.Deterministic=1`, native `UChaosCache` transform tracks and a companion fixed-scale/reference-pose channel | authoritative visible translation/rotation/fixed-scale replay at every logical frame for fixed-topology simulated `UStaticMeshComponent` bodies | persist one `.srcache`; velocity, constraint/contact/sleep and full solver state require a future engine-specific adapter |
| Third-party/custom VFX and gameplay | `SRDatasetControllable` evaluation plus optional canonical state record/apply callbacks | exact adapter state when the cached payload round-trips byte-for-byte | serialize every render-affecting private field and treat cache artifacts as private save data |
| HR/LR/Depth/reference pairing | all captures happen after the same world tick before the next simulation advance | identical logical state and camera transform | no custom render hook may mutate gameplay state |
| Rigid FG endpoint motion | isolated forward/reverse processes plus `FMotionVectorSimulation` endpoint transforms | independently captured `motion_1_to_0` and `motion_0_to_1` for scene components | opaque reverse event state still needs an adapter/cache |
| Skinned FG endpoint motion | cache current component-space bones at each captured endpoint, overwrite the editable previous double buffer, then force the renderer's previous-bone update | analytic fixture and real project AnimBP pose-cache replay pass forward/reverse gates | AnimBP state driven by external gameplay must be deterministic while the portable cache is recorded |
| WPO FG endpoint motion | material-authored `PreviousFrameSwitch` with explicit current/previous world offsets; force and record `r.Velocity.EnableVertexDeformation=1` | shipped WPO fixture passes analytic forward/reverse native Velocity gates | project WPO, Material Parameter Collections and animated materials need the same explicit previous-state contract and non-fixture validation |
| Time-driven materials | override `FSceneViewFamily` game time from the logical frame, supply signed previous time, freeze real time at a stable nonzero value | ordinary Game Time expressions replay forward/reverse at the requested logical frame | real-time/external/MPC/custom material state needs an explicit adapter and project validation |
| Screen-space UI | render `SGameLayerManager` through `FWidgetRenderer` without the enclosing scene viewport | display-size RGBA with premultiplied RGB and straight coverage alpha | world-space `UWidgetComponent` is rejected while visible/registered |
| Scene-control coverage | pre-warmup inventory of ticking Actors/components, loaded Niagara DIs and known time/random material expressions | canonical report, counts and SHA-1 before frame zero | strict jobs must classify every record as built-in/interface controlled or an exact audited class exception |

“Absolute control” therefore means the plugin owns time and every participating system is either covered by a built-in driver or explicitly implements the control protocol. Unsupported live inputs are not silently certified as deterministic.

## Output contract

- The current backend emits `spatial-sr-data-v1` and is certified only for single-frame spatial SR. It deliberately records `temporalTrainingCertified=false` and rejects `nr-sr-data-v2`/`nr-fg-data-v1` jobs until the Main View/RDG backend supplies their mandatory buffers.
- Frame numbers are inclusive and expressed in the job's rational frame rate.
- Every written frame separates `logicalFrameId` from its actual `renderSubmissionId` values. Render submissions never advance scene simulation; each reference modality owns a persistent SceneCapture view state, while optional temporal diagnostics use the persistent player Main View state.
- HR/LR PNG uses `SCS_FinalColorLDR`: display-referred, tonemapped output. It is not pre-tonemap linear HDR and must not be labelled as such.
- Legacy `depth/` is `SCS_SceneDepth` in Unreal centimeters. The temporal path separately stores raw reversed-Z device depth, linear view depth in meters and a validity mask.
- `color_lr_scene_hdr` is real Main View AfterDOF linear scene RGB before the Temporal Upscaler. It records pre-exposure, current/previous jitter and complete view/projection transforms.
- `color_hr_native_scene_hdr` is an isolated non-jittered HR view. `color_hr_reference_scene_hdr` renders at 2x-4x spatial resolution and is filtered back to the same fixed HR output grid without simulation/history advance.
- `color_main_view_hudless_after_tonemap` is captured after tonemap and before Slate/UI composition. The capture preflight and per-tick guard reject every visible registered `UWidgetComponent`; custom mesh-authored UI still requires a project label/policy because it is indistinguishable from ordinary scene geometry.
- `ui_color_alpha` is an independent display-size PNG from the Slate game-layer tree, with no scene backbuffer. RGB is premultiplied by coverage and Alpha is straight coverage.
- `object_id` reads Custom Stencil as an integer in `[0,255]`; zero is unlabeled.
- PNG and EXR writes use a temporary `.part` file followed by an atomic rename.
- Since 0.17, resume only reuses a complete spatial dataset after checking the original manifest, plugin/engine/world, normalized job (only `bResume` may differ), frame IDs and original file hashes. The original manifest is preserved byte-for-byte. Partial and temporal resume are rejected; fresh capture defaults to `bResume=false`.
- The manifest records the complete normalized job, engine version, state, pairing rule, camera pose and SHA-1 of each encoded file.

## Reproducibility acceptance test

For a candidate scene:

1. Delete or select two empty output roots.
2. Run the same job twice with the same cooked/editor build, RHI, GPU driver and content revision.
3. Run `ValidateDataset.py <run-b> --compare <run-a>`.
4. Metadata and non-color buffers must meet their exact gates. A color mismatch is accepted only when it meets the versioned numeric tolerance; the validator writes a heatmap for inspection.
5. A failed required check is a determinism violation. Move the differing system into Sequencer, enable its native deterministic/cache mode, or implement `SRDatasetControllable`.

Cross-GPU bit-identical floating-point rendering is not guaranteed by Unreal. Training-set provenance should therefore also pin GPU model/driver, RHI, engine changelist, project commit and console-variable profile.

Each frame also records a CPU scene-state SHA-1. Its sorted canonical input covers Actor identity/class/transform/visibility/tick/interface ownership, SceneComponent state/transforms, every current component-space skeletal bone transform, Niagara asset/age mode/desired age/seed/solo/seek settings and Cascade asset/activity. Actor paths that tick without `SRDatasetControllable` are emitted as an audit list. This scene hash deliberately excludes Niagara/Cascade GPU particle bytes, material/WPO shader state, Chaos internal solver state and opaque third-party buffers. Native Niagara caching therefore has a separate artifact/topology/payload channel. Native Chaos caching likewise has a separate artifact/topology/reference-frame channel with explicit transform tolerances, so the validator does not confuse a textual double-precision scene-hash difference with failure of the stronger logical-frame rigid-pose gate.

Before warmup, `scene_control_preflight.json` separately classifies registered ticking Actors and components, every Data Interface reachable from active Niagara component overrides/system exposed parameters/runtime instance parameters/resolved scripts, and material `Time`, `PerInstanceRandom` and `ParticleRandom` expressions reachable from loaded primitive materials/functions/layers. Logical-time expressions and Niagara particle random are classified as controlled only when their corresponding drivers are enabled. Strict mode rejects any remaining record before frame zero. Exact or trailing-wildcard class rules are explicit audited exceptions; they do not change simulation behavior and must not be confused with a deterministic adapter.

## Temporal certification boundary

The implementation now captures pre-exposed linear HDR Color, decoded raw Velocity and coverage, camera-completed current-to-previous Motion, device/linear depth plus validity, current/previous jitter, exact jittered/unjittered matrices, exposure/pre-exposure, reactive/transparency masks, Object ID, same-pixel deferred world normal/Base Color/roughness/metallic/specular, isolated HR native/reference outputs, HUD-less display color and independent UI RGBA. It also blocks on engine streaming before the first sample, hashes sorted `UTexture2D` residency state per frame, snapshots Mip/LOD/streaming CVars and reads the actual material texture Mip bias from each GPU View Uniform. A paired-process gate swaps the actual auxiliary render order between `HR -> Reference -> LR -> Depth` and `LR -> Depth -> HR -> Reference`, requires normalized provenance equality and compares every output. The v0.5.0 gates additionally prove component-space bone deformation, exact cached project AnimBP poses, project animated-material logical time, explicit `PreviousFrameSwitch` WPO, labeled skeletal disocclusion and zero visible `UWidgetComponent` residue. The v0.6.0 gates add explicit Static/Camera-only/Object-only/Mixed analytic motion, a full four-quadrant jitter cycle and hashed strict scene-control preflight. The v0.7.0 gate extracts the existing native-LR SceneCapture at the Main View's AfterDOF stage, proves exact camera/projection alignment, normalizes independent pre-exposure and performs metadata-jittered subpixel pixel comparison without another render submission. The v0.8.0 gate finalizes a fixed primitive-component topology after warmup/streaming, assigns collision-free uint8 stencil IDs in stable path order and hashes a semantic ID map; any later set or label drift fails before writing the frame. The v0.9.0 gate adds explicit disocclusion mask/valid/reason outputs and independently reconstructs every non-reset decision from saved current/previous motion, depth and IDs; unresolved dynamic same-instance surface identity is rejected with validity zero. The v0.12.0 gate reads deferred GBuffer values from the exact Main View input pixel, rejects Forward Shading, locks the Scene View state/output frame index to logical time, and validates attribute semantics plus cross-process quantization limits. `nr-sr-data-v2` nevertheless remains disabled until dynamic per-surface/wider instance identity, Main View/reference-HR pixel-domain comparison and broader non-fixture scene coverage all pass. Adding placeholder metadata or renaming a SceneCapture output is not acceptable.

Validator v15 adds a deterministic `datasetProfile` built only after each frame's hashed buffers pass integrity checks. It reports temporal motion buckets, valid and uncertain rejection, reactive/transparency coverage, depth/luminance distributions, edge/high-frequency energy, exposure change and camera speed. Reset frames are excluded from temporal distributions. Profile coverage is required, but diversity thresholds remain diagnostic: a short static acceptance capture must not be mislabeled as a balanced training corpus, and a warning must not relax any buffer contract.

Version 0.11 adds an opaque-state proof channel to `SRDatasetControllable`. After logical-time evaluation and fixture/camera placement but before any selected render, strict jobs call `DatasetGetDeterministicState()` on every controllable and reject empty results. The subsequent sorted scene-state hash includes each Actor path, state SHA-1 and UTF-8 byte count; frame JSON exposes the same digest records without persisting private raw state. This proves adapter-supplied state, but it does not synthesize a Niagara/Chaos/gameplay cache for systems that have no adapter.

Version 0.14 makes adapter-owned state portable without weakening that default privacy boundary. Recording mode calls `DatasetGetDeterministicState()` on every controllable for every logical frame, including unselected simulation frames, and atomically writes a schema-v1 JSON artifact with world-relative Actor path, exact class, raw canonical payload, payload SHA-1/UTF-8 size and a per-frame aggregate hash. Recording is Standard-only and non-resumable. Replay mode requires the exact Actor/class set, invokes `DatasetApplyDeterministicState()` in `OnWorldPostActorTick` before end-of-frame render-data submission, then reads the state back and requires byte equality plus the saved SHA-1. The validation probe deliberately derives its transform from process-local private state; validator v19 requires it to differ before application while the restored scene/image/depth results match the recording process. This is a generic adapter cache, not automatic serialization of arbitrary UObject memory or Chaos solver internals.

Version 0.15 adds a separate native Niagara Sim Cache channel. Recording enumerates active registered components in case-sensitive world-relative path order, requires fixed path/system-asset topology, begins one `UNiagaraSimCache` per component and writes exactly one all-attribute frame per logical frame after Niagara finalization. GPU emitters use `FNiagaraDataSetReadback` immediate readback. The atomic binary envelope binds magic/schema, exact engine/world/policy, inclusive frame range, rational rate, random seed, component/system identity, CPU/GPU emitter counts, cumulative particle samples and per-payload SHA-1. Replay deserializes before scene control, requires the exact runtime topology, attaches the cache, drives Desired Age and verifies readable frame/payload metrics before every render submission. Rebasing, interpolation/extrapolation, custom Data Interface storage and bulk-data serialization are disabled; the loader bounds each component payload at 1 GiB. Validator v20 checks the envelope header/hash, manifest topology and record/apply roles and then tolerance-compares every rendered modality. The artifact is authoritative: repeated live GPUComputeSim recording is not promised byte-identical (the validation CPU payload repeated exactly, while the GPU payload hash changed), so deterministic dataset production preserves one artifact and replays it. This closes replay of the declared fixed-topology native CPU/GPU payload, not byte-identical GPU re-simulation, arbitrary external Data Interface resources or Chaos state.

Version 0.16 adds a native Chaos rigid-body transform channel. Recording discovers registered, simulating, non-transient `UStaticMeshComponent` bodies supported by UE 5.7's Chaos static-mesh cache adapter, freezes their case-sensitive topology and serializes one `UChaosCache` per body into an atomic schema-v1 `.srcache`. The envelope binds engine/world/policy/frame range/rational rate/seed, Actor/component/class/static-mesh identity, initial pose and fixed scale, native payload hashes and a sorted exact reference pose for every logical frame. Native caches may compress transform keys, so recorded logical-frame count is authoritative rather than raw key count. Replay loads before capture, lets the native manager provide its kinematic pre-solve path, random-accesses cache time `(frameIndex + 1) * fixedDelta`, verifies native translation/rotation within `0.05 cm`/`0.05 degrees`, preserves component scale and applies the artifact's exact reference pose in `OnWorldPostActorTick` before any dataset render submission. Validator v21 requires record/apply roles, exact artifact/topology/reference hashes, two moving bodies, real hit events and the bounded native error on all 18 frames. This is authoritative visible rigid-pose replay, not solver restart: velocities, angular velocities, forces, constraints, contacts, sleep/island state, Geometry Collections and deformables are not serialized.

Version 0.12 binds both `OverrideFrameIndexValue` and `OverrideOutputFrameIndexValue` to logical frame plus phase whenever logical jitter locking is active. This engine-supported sequence hook is applied before visibility/base pass and is recorded beside the actual GPU View values. It prevents material dithering and other View-frame stochastic consumers from inheriting process-uptime submission counts. The deferred attribute readback has a separate reproducibility contract: validity/structure remain exact; sparse quantized values at raster/material boundaries have strict per-modality changed-pixel, mean, p99 and maximum bounds with generated heatmaps.

### Stable instance identity

Stable-ID mode snapshots every registered, render-capable, non-visualization `UPrimitiveComponent` after warmup and the streaming barrier. Case-sensitive component-path sorting defines initial IDs `1..N`, with `0` reserved for background. The subsystem saves the prior Custom Depth enable flag, stencil write mask and value, applies unique labels, and writes `instance_id_map.json` with component/Actor/class paths plus a canonical SHA-1. Fixed mode recollects the topology before every selected capture and requires the exact path order, ID, write mask and Custom Depth state.

Version 0.13 adds an explicit dynamic mode. New component paths discovered at a selected frame are sorted, assigned monotonically increasing uint8 IDs and appended to schema-v2 mapping records with `firstSeenLogicalFrame`; IDs are never reused after removal. A path-stable respawn receives its previous ID but a path whose Actor/component/class identity changes is rejected. The final allocator mapping/hash is propagated back to all in-memory frame records, while every frame retains exact active/new ID arrays. Resume is rejected until a persistent allocation journal exists. Finish/failure restores every still-live or respawned component's prior stencil state. The runtime spawn/remove fixture proves map counts `60 -> 61`, active counts `60 -> 61 -> 60` and exact replay across processes. The Custom Stencil carrier remains limited to 255 identities, and component identity still cannot resolve same-component triangle/deformation self-occlusion; v0.9 exposes those pixels as conservative reject-invalid rather than false supervision.

Frame generation uses isolated forward-endpoint, reverse-endpoint and intermediate replay roles. Its intermediate `Sτ` cannot update either endpoint's previous state. The forward process evaluates `t0 -> t1` and captures `motion_1_to_0`; the reverse process evaluates `t1 -> t0` and captures `motion_0_to_1`. Both span the full endpoint interval for SceneComponents, the controlled double-buffered skeletal fixture, cached project AnimBP poses and the explicit-previous WPO fixture; neither field is synthesized from the other. Reverse Sequencer evaluation uses absolute jumps. Adapter-owned event/opaque state can be restored by the v0.14 controllable-state cache, and fixed-topology Niagara CPU/GPU systems by the v0.15 native Sim Cache; autonomous systems outside those protocols remain dedicated cache/replay requirements.

### Experimental RDG diagnostic path

The UE 5.7 `AfterDOF` scene-view-extension callback reads the `SceneColor`, `GBufferVelocity`, `SceneDepth`, deferred Scene Texture uniform buffer, separate translucency and Custom Stencil resources associated with the real player view. A compute pass decodes UE Velocity, fills uncovered static pixels from depth and `ClipToPrevClip`, converts motion to display pixels/top-left origin, linearizes depth to meters, derives validity/reactive/transparency channels, copies Object ID, decodes world normal/Base Color/roughness/metallic/specular with `GetGBufferData` at that exact input pixel, and writes exact View uniform metadata to readback. The four GBuffer outputs share `depth_valid`; invalid sky/no-opaque pixels are zero. A second extension copies display-resolution scene color after tonemap but before Slate/UI. Temporal preparation fails when `r.ForwardShading != 0` instead of fabricating missing deferred attributes.

Two request modes exist: persistent native-LR SceneCapture and real player Main View. The Main View runner fixes the viewport to HR, locks `r.ScreenPercentage` to the LR/HR ratio, disables dynamic resolution, filters out SceneCapture views, and defers sample commit until the next pre-actor callback so the real view has rendered without advancing the logical state. When comparison is enabled, the extension first extracts only `SceneColor` from the already scheduled LR SceneCapture, releases that request, then arms the Main View request. The comparison therefore adds readback but no render submission, world tick or history advance.

The real Main View path has produced the requested LR render rect, non-zero TSR jitter and valid HDR/Motion/Depth/Object-ID/mask/GBuffer buffers in D3D12 tests. The semantic fixture verifies moving-object direction/magnitude, reset motion, Velocity coverage, 1/10/100 m depth, reversed-Z reconstruction, transparency and occlusion/disocclusion geometry. Geometry, validity, motion and identity outputs replay exactly in the checked fixture. Lumen-dependent color and sparse quantized GBuffer boundary values are numerically gated rather than promised byte-identical across processes.

Capture order is a job-level enum rather than a metadata-only label. Each SceneCapture is actually submitted in the selected order, warmup follows the same ordering, and submission IDs are assigned and serialized in execution order. The v0.4.1 paired fixture recorded both opposite orderings and passed 599/599 required checks with the bone and WPO gates enabled. Color uses the same numeric reproducibility policy as clean replay; the earlier v0.3.2 gate's worst HUD-less pair measured 59.1 dB PSNR.

The capture also exports `depth_previous_reprojected_device`, `history_rejection_mask`, `history_rejection_valid` and `history_rejection_reason`, plus exact `disocclusion_*` aliases. At a motion-reprojected previous pixel, a component-ID mismatch is definitive cross-instance rejection. Static/camera-only pixels compare prior visible Reversed-Z depth with the current surface reprojected into the previous camera. Resets and out-of-bounds reprojections are exact rejections. Velocity-covered same-instance or unlabeled pixels are conservatively rejected with validity zero because component identity and camera-only previous depth cannot prove per-surface correspondence under rigid/deforming motion. Integer reason codes distinguish all nine paths. Validator v14 reconstructs the grid from saved current/previous buffers and requires exact equality. The mask is training-usable only when gated by validity and remains explicitly production-uncertified for dynamic same-instance self-occlusion.

## Experimental FG isolation and assembly

Forward endpoint replay captures `t0, t1, ...` while suppressing player Main View submissions between endpoints. Before each later endpoint render, the subsystem supplies the last captured `USceneComponent` transforms through `FMotionVectorSimulation` and overwrites double-buffered `USkinnedMeshComponent` previous component-space bones before forcing the renderer's previous-bone update. Reverse endpoint replay starts at `t1`, walks toward `t0`, and supplies the saved future component/bone state when rendering the earlier endpoint. The validation WPO material takes separate current/previous world-offset parameters through `PreviousFrameSwitch`, so its vertex shader follows the same interval without moving the component. Per-frame metadata records logical evaluation direction, `motionPreviousLogicalFrameId`, the absolute time span, bone component/count/skip evidence and the limited WPO scope.

All FG roles lock the temporal jitter index to `(logicalFrameId + phaseOffset) % sequenceLength` through `r.TemporalAA.Debug.OverrideTemporalIndex`, while the full uint32 Scene View state/output frame index is logical frame plus phase. The feature deliberately requires a non-shipping capture build. Assembly compares the actual per-view jitter vectors and camera/exposure metadata, then requires byte-exact device/linear depth, depth validity, Object ID and motion-validity hashes at matching forward/reverse logical frames. A full scene-state mismatch is rejected for production data. Only the explicit semantic fixture may retain a documented mismatch from hidden uncontrolled actors, and that exception keeps the result uncertified.

Intermediate replay runs in a separate process and allows exactly one captured offset frame. This prevents a previous intermediate from becoming the retained Main View history for a later sample. A dataset producer launches one such process per endpoint pair until a restartable world-state cache is implemented.

`AssembleFrameGenerationDataset.py` accepts only completed core source captures whose v9 validation reports pass. It requires the rigid, bone and WPO fixture categories in all three processes, verifies engine, GPU, content, shader, streaming-residency and normalized CVar provenance; the sole intentional CVar difference is `r.MotionVectorSimulation` (`1` for both endpoint directions, `0` for the intermediate). Optional paired arguments add validated project AnimBP and project animated-material captures. The assembler copies their manifests, reports, cross-direction comparisons and shared pose-cache artifact into the self-contained dataset, then rechecks every hash through an atomic staging directory.

`ValidateFrameGenerationDataset.py` then checks the self-contained pair, paths, hashes, EXR shape/range/finiteness, midpoint time, camera matrices, exposure, both endpoint histories, bidirectional motion/rejection semantics, three-process provenance and endpoint-grid alignment. For the designed semantic fixture it rejects a reverse field fabricated by same-pixel negation and independently re-measures WPO motion under Object ID 41 in both assembled direction buffers. When project evidence is present it revalidates the exact shared pose-cache SHA-1/application proof, labeled skeletal reveal/occlusion masks, project material identity/logical-time color comparison and zero-world-widget policies. A successful report is an integrity pass, not FG certification. In the checked project the sole manifest requirement still open is project-authored WPO endpoint-motion validation because the project contains no such asset.
